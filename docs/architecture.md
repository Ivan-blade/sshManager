# 架构文档

> 适用版本：核心闭环已实现（2026-08-01）。本文件描述**已落地**的架构；规划中的能力见文末「演进方向」。

## 1. 项目定位

`sshManager` 是**人机协作的 SSH 工具（xshell 增强版）**：人和 AI 在同一个浏览器界面里协同操作终端会话。人和 AI 各自有独立的执行策略，但共享同一个终端会话——人通过界面输入，AI 既可以通过后端接口写入共享终端（协同），也可以纯后端独立执行命令（独立）。

## 4. 关键设计决策

### 4.1 pty 所有权在 Python 后端（核心决策）

- 终端会话的 pty 由 **Python 后端持有**；前端和 AI 都只是这个 pty 的「客户端」。
- **AI 干涉走纯后端接口**（向共享 pty 写字节），不依赖前端 JS——避免对浏览器的依赖。
- 附带收益：Electron 壳将来可剥掉，退化为纯浏览器形态；前端只通过 HTTP/WS 与后端通信。

### 4.2 AI 双执行路径

| 路径 | 接口 | 语义 | 并发 |
|------|------|------|------|
| 协同 | `POST /write` | 向共享终端注入数据，输出进缓冲并对所有订阅者回显（人能看到） | 有，靠写锁缓解 |
| 独立 | `POST /exec`、`POST /find` | 非交互式执行，直接返回 stdout/stderr/exit_code，不经过共享终端 | 无，**默认优先** |

设计理念：AI 默认走独立路径避免并发；需要人介入/共享时才走协同路径。

### 4.3 增量输出缓冲（防止全量拉取撑爆上下文）

- 每个会话维护**有界环形缓冲**（上限 256KB，见 `config.TERMINAL_BUF_LIMIT`）。
- `GET /buffer?since=N` 只返回 `N` 之后的新增内容；`gap=true` 表示调用方偏移已超出缓冲窗口（需要全量同步）。
- 这对应原设计「AI 通过 getBuffer **增量获取**终端信息」的服务端实现。

### 4.4 单一写入队列

- 所有来源的输入（人的 WS input、AI 的 write 接口）通过**同一把 asyncio 锁**串行写入 pty，缓解人机并发导致的字节交错。

### 4.5 AI 能力发现（自举）

- `GET /api/ai/capabilities`：能力概述（轻量），`GET /api/ai/capabilities/{name}`：按名称查参数详情。
- body 参数 schema 从 **Pydantic 模型** `model_json_schema()` 推导，保证与实际校验一致。
- AI 不硬编码接口，先查清单再查参数再调用；AI 执行面无前端界面。

### 4.6 传输层抽象

- `Transport` 统一接口：`connect / close / exec / create_interactive`。
- **SSH**（asyncssh）：exec 走 `conn.run`；交互走 `create_process`（pty 分配），连接复用（多路复用通道）。
- **本地**（`pty.fork()` + `loop.add_reader`）：开发/验证用，与 SSH 共用同一套上层代码路径。
- 上层（终端流 / AI 执行面 / SFTP）完全不知道底层是 SSH 还是本地。

## 5. 数据流

### 5.1 终端 I/O 流（人机共享）

```
浏览器 xterm ──ws input──▶ 后端 ──写锁──▶ pty ──▶ shell/远端
浏览器 xterm ◀──output── 后端 ◀──读循环── pty
                          │
                          └──▶ 追加到环形缓冲 + 扇出给所有 ws 订阅者
```

### 5.2 AI 协同路径

```
AI → POST /write {data} → 写锁 → pty → 输出进入缓冲 → 前端 ws 回显（人看到）
```

### 5.3 AI 独立路径

```
AI → POST /exec {command} → 独立连接/子进程 → 直接返回 {stdout, stderr, exit_code}
AI → POST /find {path, pattern} → 后端执行 find（shlex 安全引用）→ 返回结果列表
```

### 5.4 SFTP（复用连接）

```
POST/GET /sftp/* → SSH: 复用会话连接上的 SFTP 通道（asyncssh start_sftp_client）
                  Local: 映射本机文件系统（开发验证）
```

## 6. 配置

| 配置 | 默认值 | 说明 |
|------|--------|------|
| `SSHMANAGER_PORT` | `8747` | 后端端口（避开常用端口），Electron 与后端读同一变量 |
| `SSHMANAGER_RELOAD` | `1`（开发） | Electron 拉起时为 `0` 关闭热重载 |
| `data/sessions.json` | — | 会话配置持久化（已 gitignore） |
| `data/groups.json` | — | 分组配置持久化（已 gitignore） |
| `TERMINAL_BUF_LIMIT` | 256KB | 会话输出缓冲上限 |

## 7. 演进方向（规划中）

1. **AI 模型接入**：把 LLM 的意图解析/输出理解接到 exec/write/buffer 接口上，形成 agent 循环。
2. **AI 后台 WebSocket 长连接** + 回显浏览器，实现「一起干」协作模式。
3. **快捷命令**分组 + 增删查改 + 组间移动 + 导入导出。
4. **会话导出/导入 UI 增强**与密码加密存储。
